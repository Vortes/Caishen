The docs also need reconciliation

The shared foundation is mostly covered

Button, IconButton, Checkbox, Switch, SegmentedControl, Tabs, Card, Tooltip, Tag, Toast, and Skeleton have topic guidance. Row selection has a shared hook and stylesheet with detailed rules. Calendar is the only JSX component file in src/components/ui with no topic coverage. This is file-level coverage, not a claim that every prop and state has been documented.

Most remaining work is pattern documentation

Do not create a generic primitive for every feature form. Establish the common field, row, surface, menu, and feedback contracts; then document domain compositions such as sharing and reconciliation against those contracts. Existing semantic tokens and closed primitive APIs are useful foundations.

A practical consolidation order

1. Document the contracts

Start with tables/rows, fields/validation, menus, and overlay surfaces. Add Calendar coverage immediately. Name current implementations and explicit alternatives; define defaults, states, keyboard behavior, responsive behavior, and one real example.

2. Choose shared owners

Decide the shared home for row layout, field wells, ChoiceField/PayeeField, popover/dialog chrome, and funding displays. Preserve feature-specific data and accounting behavior in their domain compositions.

3. Reconcile and enforce

Resolve the listed mismatches and narrow exceptions. Refresh stale examples and TODOs. Add enforcement only after the missing building blocks exist; raw-element counts today measure migration scope, not automatic violations.
